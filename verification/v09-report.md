# Memory Palace OS V0.9 — AI教材理解与证据验证报告

## 实现范围

1. 新增 OpenAI-compatible Chat Completions 知识理解适配器，可通过独立环境变量配置。
2. 新增离线规则基线，未配置真实模型时可运行。
3. 输出概念、公式、条件、步骤、机制及其关系，并对每条提取记录保留原文证据片段。
4. 本地验证器检查字段结构、领域枚举、特征取值、概念ID、关系端点和证据片段是否逐字出现在源文本中。
5. 将AI提取的特征向量交给现有技能基因库，生成预算受限的记忆策略候选。
6. 新增 `/api/knowledge/understand` API。

## 测试结果

- 全量自动化测试：110/110通过。
- 本地证据核验：通过伪造引文与悬空关系端点反例测试。
- 远程模型适配器：使用模拟HTTP响应验证JSON Schema请求格式、响应解析与本地证据核验；未进行真实供应商联网调用。
- HTTP端点：本地离线模式端到端测试通过。
- 完整 TypeScript `typecheck`：未通过，运行环境缺少 `@types/node`。Node.js 22.16 的 TypeScript strip 运行和全量测试通过，不等于完整静态类型检查通过。

## 重要限制

- 远程模型需要用户自行配置兼容供应商、模型名和密钥；本次没有使用用户密钥，也没有声称完成真实模型调用。
- 原文证据校验只能证明引文存在于输入文本，不能证明模型给出的关系类型、概念解释或摘要在语义上正确。
- 语义关系检查仅提供关键词警告，不能代替专家审查。
- 当前输入接口接收纯文本。PDF/图片OCR与表格/图形解析尚未实现；需先由文档解析层提取文本并保留页码/坐标，再接入同一知识理解管线。
- AI策略建议仍是候选，必须经过用户确认，不会自动覆盖原始知识或发布到宫殿。

## 验收结论

V0.9 建立了“模型提取—原文证据核验—策略候选生成”的可运行纵向链路。真实模型质量、外部教材泛化、图表理解和真人记忆效果仍需单独实验。
