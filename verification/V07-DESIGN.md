# Memory Palace OS V0.7 — 跨领域记忆技能迁移与组合泛化

## 1. 本版目标

V0.7 在 V0.6 的模块化认知引擎旁增加一套独立的跨领域技能迁移子系统。原 V0.1–V0.6 的数学解析、知识校验、记忆联想、遗忘估计、认知流水线和旧 API 均保留。

本版回答四个工程问题：

1. 一个领域中有效的记忆技能，能否按知识结构特征迁移到未参与训练的领域？
2. 多个基础技能能否通过依赖关系和组合规则形成更高阶策略？
3. 技能本身的参数能否以有界、可追踪的基因版本方式进化？
4. 在训练领域与测试领域隔离、且测试组合在训练中未出现时，进化策略是否仍有收益？

## 2. 新增模块

- `src/cognition/transfer-types.ts`：领域、特征、技能基因、等位变体、策略基因组、任务和指标类型。
- `src/cognition/transfer-library.ts`：13个版本化技能基因及其特征亲和、来源领域、迁移性、依赖和计算成本。
- `src/cognition/transfer-graph.ts`：依赖闭包、DAG拓扑排序、基因组校验、默认策略。
- `src/cognition/transfer-engine.ts`：仅依据公开领域与知识结构特征计算技能激活；执行依赖闭包、计算预算约束与评测。
- `src/cognition/transfer-evolution.ts`：等计算预算下的固定策略搜索、静态模块组合搜索、遗传变异/交叉搜索；变异可产生有界、版本化技能等位基因。
- `eval/v07-transfer.ts`：跨领域和组合留出数据生成、独立实验、配对比较、JSON/CSV/Markdown报告。
- `test/transfer.test.ts`：基因库、依赖图、缺失依赖、特征迁移、隐藏标签隔离、预算、突变、数据切分和HTTP API测试。

## 3. 技能基因库

基础技能包括：

- `atom-chunking`：原子知识拆分根技能。
- `spatial-route`：空间路线编码。
- `symbol-anchor`：符号视觉锚定。
- `causal-chain`：因果链组织。
- `contrastive-pair`：对比辨析。
- `timeline-sequence`：时间/步骤序列。
- `hierarchy-chunk`：层级组块。
- `dual-code`：语言与图像双重表征。
- `analogy-bridge`：跨域关系映射。
- `mechanism-simulation`：动态机制模拟。
- `retrieval-cue`：提取线索设计。
- `interleaved-retrieval`：交错提取。
- `semantic-boundary`：语义边界辨析。

技能的 `featureAffinity` 是工程设计的先验特征权重，不是从真人实验中拟合的心理参数。`sourceDomains` 只产生很小的来源领域先验，主要迁移判断依赖结构特征，而不是简单按学科名称查表。

### 技能等位基因进化

策略基因组可以携带 `alleles`：

- 对单个技能的特征亲和权重进行小幅变异。
- 对迁移性和计算成本乘数做有界变异。
- 记录版本、父版本和变异原因。
- 交叉时合并父代等位基因参数。
- 只允许修改已注册技能的参数，不生成或执行任意代码。

等位基因约束：特征权重 `[0, 1.2]`、迁移性 `[0.4, 1]`、成本乘数 `[0.75, 1.5]`。变异结果必须经过依赖图和参数校验。

## 4. 依赖图与组合

`requires` 表示技能的前置技能。例如：

- `mechanism-simulation` 依赖 `causal-chain`。
- `interleaved-retrieval` 依赖 `retrieval-cue` 和 `contrastive-pair`。

`createTransferGenome()` 会自动补齐依赖闭包；`validateTransferGenome()` 检查未知技能、缺失依赖、重复基因、非法等位基因、非法协同对和预算参数。依赖图使用拓扑排序检查环。

运行时先根据知识结构特征计算技能激活，再按激活度选择技能；必要依赖随技能一起加入。根技能 `atom-chunking` 始终保留。计算预算不足时跳过低激活候选，不超出用户指定预算。

## 5. 迁移与组合泛化实验

运行命令：

```bash
npm run transfer:experiment
```

固定随机种子生成器，24个独立训练/测试重复。每次：

- 源训练领域：概率、程序设计、历史。
- 目标领域留出：数字逻辑、语言、生物。
- 组合留出：`causal+symbolic`、`analogical+retrieval`、`hierarchical+spatial`、`contrastive+sequential` 四种结构特征对。
- 每次72条源领域训练任务、72条目标领域留出任务、48条组合留出任务。
- 三个策略臂：固定启发式、静态模块组合、进化模块组合。
- 每个策略臂恰好评估40个候选；训练集相同；每个候选的计算预留相同；每个任务的推理预算上限相同。

搜索预留预算：

`40 × (1 + 72 × 18) = 52,240` 个确定性记账单位/策略臂。

这些单位是为了保证实验臂之间可比的确定性预算，不是CPU秒、能耗或Token数量。实际平均推理成本另行报告。

### 数据隔离

- 目标领域不进入源训练集。
- 四种组合留出对不进入训练任务的主导特征对。
- 进化策略只看到公开的 `domain` 与 `features`。
- `hidden.skillUtility` 和 `hidden.synergyPairs` 仅供模拟器评分，策略选择代码不得读取。
- 训练和测试使用不同随机种子范围。

### 指标

- `normalizedUtility`：相对于模拟器可用技能效用上界的归一化收益。
- `featureFit`：选中技能对任务结构特征的平均匹配度。
- `combinationCoverage`：至少激活两个可组合技能的任务比例。
- `novelCombinationCoverage`：测试时激活的技能对中，源训练任务从未共同激活过的技能对覆盖比例。
- `meanComputeUnits`、`budgetUtilization`：实际执行成本。

按24个独立重复计算策略间配对差值，报告正态近似95%区间。该区间是描述性统计，不做多重比较校正。

## 6. HTTP API

### 获取技能目录

`GET /api/transfer/skills`

### 获取默认迁移策略

`GET /api/transfer/default-genome`

### 组合策略

`POST /api/transfer/compose`

```json
{
  "id": "my-transfer-strategy",
  "geneIds": ["symbol-anchor", "causal-chain", "mechanism-simulation"],
  "activationThreshold": 0.24,
  "maxActiveGenes": 5,
  "synergyPairs": ["causal-chain+mechanism-simulation"]
}
```

依赖会自动补齐。

### 校验策略

`POST /api/transfer/validate-genome`

```json
{ "genome": { "...": "TransferGenome" } }
```

### 选择目标任务的记忆技能

`POST /api/transfer/select`

```json
{
  "task": {
    "id": "cmos-nand-01",
    "domain": "digital_logic",
    "difficulty": 0.4,
    "features": {
      "spatial": 0.1, "symbolic": 0.9, "causal": 0.85,
      "sequential": 0.2, "hierarchical": 0.7, "contrastive": 0.1,
      "analogical": 0.1, "dynamic": 0.85, "retrieval": 0.3,
      "semantic": 0.1
    }
  },
  "budgetUnits": 18
}
```

生产 API 不接受 `hidden` 评测字段，避免客户端将模拟器答案注入策略选择。该 API 只给出技能选择建议，不自动改写知识或发布联想场景。

## 8. 科学与工程边界

这是一个可复现的合成工程基准，不是真人记忆研究。技能基因特征亲和由开发者设计，模拟器的隐藏效用也依赖这些设计，因此结果可能受到基准与技能库共享假设的影响。目标领域留出能检验代码层面的跨领域特征迁移，但不能证明真实学生在新学科中会获得相同迁移收益。

下一步应由外部人员编写任务集、盲标知识结构特征，并开展真人交叉实验；还需要估计特征标注误差、技能迁移负效应和不同用户的个体差异。当前所有基因 `evidenceLevel` 均为 `designed`，没有任何技能被标记为 `human_validated`。

## 9. V0.7 留出实验结果（本次实际运行）

本次运行使用24个独立重复，每个重复72条源训练任务、72条目标领域任务和48条组合留出任务。每个策略臂40个候选、18单位/任务推理上限；每臂预留预算为：

`40 × (1 + 72 × 18) = 51,880` 个确定性记账单位/重复。

| 策略 | 目标领域效用 | 组合留出效用 | 合并效用 | 未见技能组合覆盖 | 平均推理单位 |
|---|---:|---:|---:|---:|---:|
| 固定启发式 | 0.7757 | 0.9570 | 0.8482 | 0.4042 | 9.69 |
| 静态模块组合 | 0.3883 | 0.7008 | 0.5133 | 0.1972 | 4.76 |
| 进化模块（允许等位变异） | 0.7966 | 0.9649 | 0.8639 | 0.5250 | 10.25 |
| 进化模块（禁用等位变异） | **0.8075** | **0.9649** | **0.8705** | **0.5500** | 10.39 |

进化模块（禁用等位变异）相对固定启发式的合并效用差值为 `+0.0222`，24个配对重复的正态近似95%区间为 `[+0.0084, +0.0360]`。这是当前合成生成器内的结果，不应外推为真人学习收益。

### 等位基因消融的负面结果

允许等位变异的进化臂平均每次搜索有8.3个候选包含变异等位基因，但最终胜出基因组平均只保留0.17个变异等位基因。与禁用等位变异的进化臂相比，合并效用差值为 `-0.0065`，95%区间 `[-0.0198, +0.0067]`。区间跨过0，未显示可靠收益；点估计反而偏向禁用等位变异。

因此，本版证明了等位基因变异机制可以运行、受约束并参与搜索，但**没有证明变异技能基因提高了迁移效果**。当前建议将其保留为实验功能，默认候选策略优先采用无等位变异搜索；后续需要改进变异算子、增加外部验证，不能把“实现了进化”当成“进化有效”。

### 分领域结果

| 策略 | 数字逻辑 | 语言 | 生物 |
|---|---:|---:|---:|
| 固定启发式 | 0.9207 | 0.4639 | 0.9426 |
| 静态模块组合 | 0.3597 | 0.2722 | 0.5329 |
| 进化模块（允许等位变异） | 0.9416 | 0.5024 | 0.9458 |
| 进化模块（禁用等位变异） | 0.9476 | 0.5235 | 0.9514 |

语言领域明显低于数字逻辑和生物，说明当前特征编码和技能库对语义/词汇任务的覆盖仍弱，不能只看合并均值。静态模块策略较差，反映本次手工技能包覆盖不足，不意味着静态模块化方法普遍无效。

### 结果解释限制

1. 技能特征亲和与合成任务生成器由同一项目设计，存在结构性假设重叠；需要外部作者独立制作任务集。
2. `normalizedUtility` 的oracle分母来自模拟器内部技能效用，不是现实中可直接观测的“记忆提升百分比”。
3. 组合留出是四组主导特征对的重组测试，不等于开放式组合推理。
4. 24次重复的区间使用正态近似，未做多重比较校正；结果是探索性工程评估。
5. 完整项目类型检查未完成：本环境缺少 `@types/node`，`npm install` 在依赖下载阶段超时。V0.7 核心迁移模块的独立严格类型检查已通过，全部100项运行测试通过，HTTP transfer API 端到端测试通过。
