# Memory Palace OS V1.0.0 — 3D交互产品纵向切片验收

## 本版目标
在保留 V0.9 知识理解与技能引擎的基础上，交付一个可本地运行的 3D 记忆宫殿工作区，而不只是继续增加后台算法。

## 已实现
- Three.js 实时 WebGL 场景：环形庭院、柱廊、知识基座、不同几何体、阴影、雾效和环境光。
- OrbitControls：鼠标拖拽旋转、滚轮缩放、视角重置。
- 知识锚点：概念、公式、条件、步骤、机制、案例采用不同形状与颜色。
- 物体选择与检查器：点击3D物体查看名称、知识原文和联想提示。
- 空间编辑：将选中物体按网格方向移动、删除、添加。
- AI知识导入：前端调用 `/api/knowledge/understand`，把解析出的概念创建为空间锚点。
- 主动回忆：显示原文线索，要求用户在3D空间点击正确锚点，并记录本轮正确率（当前为会话内统计）。
- 宫殿持久化：新增 GET/POST/PUT `/api/palaces`，将宫殿和物体写入现有本地 JSON Store。
- 静态前端服务：`/`、`/app.js`、`/styles.css`。

## 工程验收
- 全量Node自动化测试：112/112通过。
- 新增 V1.0 API 集成测试：宫殿创建、读取、列表、更新和非法对象类型拒绝通过。
- 前端 JavaScript 语法检查：通过。
- 静态资源 HTTP 服务：集成测试通过。
- 浏览器真实WebGL渲染：未在当前自动化环境中进行图形浏览器端到端测试。
- 完整 TypeScript `typecheck`：仍因环境缺少 `@types/node` 未通过；Node 22.16 strip-types 运行与测试通过。

## 重要限制
1. Three.js 与 OrbitControls 使用 jsDelivr CDN import map；浏览器需要互联网访问 jsDelivr 才能加载3D引擎。Google Fonts也使用外部资源，离线时回退到系统字体。
2. AI导入质量取决于当前知识模型配置。默认离线模式仍是规则基线，不是深层语义模型。远程模式需要用户配置兼容API和密钥。
3. PDF/图片导入、OCR、公式图片识别、表格和图示解析尚未实现。本版导入输入是纯文本。
4. 回忆训练目前是场景定位式选择题，不是完整的间隔重复系统；训练数据暂时只显示当前页面会话中的统计，不具备长期遗忘曲线。
5. 空间布局目前采用确定性螺旋位置和手动微调，不是基于房间语义与知识依赖的自动建筑规划。
6. 宫殿数据保存在服务端本地 JSON 文件，尚未实现多用户认证、云同步、加密和并发协作。

## 结论
V1.0交付了“本地启动 -> 进入真实3D场景 -> 放置知识锚点 -> 查看知识 -> 进行简单主动回忆 -> 保存宫殿”的首个可运行产品闭环。它是可交互的3D MVP，不应被描述为完整成熟的记忆训练产品。
