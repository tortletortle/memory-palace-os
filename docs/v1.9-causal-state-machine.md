# V1.9 — 单变量反事实对照实验

## Product intent

Turn the explicit state machine from a one-path simulator into a controlled comparison tool. A learner can keep the event sequence fixed, change one declared numeric input at one step, and compare the resulting state paths.

This is a model-internal intervention experiment. It does not discover causal relationships from observational data and does not prove that the model describes the real world.

## Contract

Endpoint:

`POST /api/palaces/:palaceId/state-machines/:conceptId/compare`

Request:

```json
{
  "revision": "<revision returned by GET>",
  "baselineSteps": [
    {"event":"heat","inputs":{"T":372}},
    {"event":"cool","inputs":{"T":372}}
  ],
  "interventionSteps": [
    {"event":"heat","inputs":{"T":373}},
    {"event":"cool","inputs":{"T":373}}
  ]
}
```

The server enforces all of the following before running either branch:

1. Both traces contain the same 1–40 number of steps.
2. The event name at every step is identical between the two traces.
3. Every step supplies all and only the model-declared inputs.
4. All input values are finite and within the existing ±1,000,000 bound.
5. Exactly one numeric input value differs across the entire pair of traces.

The result identifies the changed step, variable, declared unit label, baseline value, intervention value, and numeric delta. It executes both traces against the same source revision and reports each branch independently. A blocked branch is returned as structured result data rather than erasing the successful branch.

The comparison reports the first step where state transitions diverge. Two paths may diverge and later converge to the same final state; the complete traces are retained so this is not hidden by final-state-only comparison.

## Interpretation

The intervention is analogous to a controlled one-factor-at-a-time experiment inside a fixed deterministic model. It isolates one declared input change while holding event order and other input values constant.

It is not a real-world causal estimate:
- The model itself may be incomplete or wrong.
- The source evidence may be incomplete or incorrectly interpreted.
- Input unit labels are metadata; no conversion or dimensional proof is performed here.
- The result says what the encoded rules do, not what nature must do.

## Safety and persistence

- Uses the existing bounded state-machine compiler and executor.
- No user-supplied code or model-generated executable content is run.
- The compare endpoint is read-only and does not change palace data, review history, or learner state.
- Revision mismatch is rejected.
- Ambiguous or invalid transitions retain the existing fail-closed behavior.

## UI

The state-machine workspace adds a single-variable comparison panel. It clones the current event sequence as the baseline, lets the learner select one step and one declared input, and changes only that value for the intervention branch. The graph overlays the baseline path and intervention path in different colors and reports the first observed difference, each final state, and any branch error.

## Verification cases

- Threshold crossing creates different state paths.
- A numeric change that does not cross a guard preserves the same path.
- One branch can be blocked while the other succeeds.
- Zero changes, multiple changes, event-sequence changes, invalid values, and stale revisions are rejected.
- HTTP integration confirms read-only behavior.
- Static UI checks verify the compare controls exist and the frontend does not use `innerHTML` or `eval`.
