# V1.9.0 — Evidence-bound dimensional analysis

## Purpose

V1.8.0 evaluates explicit algebraic equations but cannot detect a formula whose operands have incompatible physical dimensions. V1.9.0 adds a conservative, opt-in dimensional checker. It does not infer units from prose or silently assume SI units.

## Source syntax

Unit declarations are separate clauses in the same saved evidence quote:

```text
unit(m)=kg；unit(v)=m/s；unit(E)=J；E=0.5*m*v^2。
```

- Use one declaration per variable: `unit(variable)=unit-expression`.
- Unit expressions require explicit multiplication and division: `kg*m/s^2`.
- Integer exponents from -8 through 8 are supported: `m^2`, `s^-2`. Unit expressions are limited to 64 characters.
- A bare numeric equation may be assigned an explicit unit, e.g. `unit(g)=m/s^2；g=9.81`. This is a user assertion, not a unit inferred from the number.
- Every input and output variable must have a declaration before the compiler reports `verified`.
- Partial declarations are shown as `incomplete`; the engine deliberately does not certify only the annotated fragment.
- No declarations preserve the V1.8 numeric-only behavior and are reported as `not_provided`.

## Supported symbols

SI base units: `m`, `kg`, `s`, `A`, `K`, `mol`, `cd`.

Derived units: `Hz`, `N`, `Pa`, `J`, `W`, `C`, `V`, `ohm`, `F`, `Wb`, `T`.

Dimensionless symbols: `1`, `rad`.

The implementation checks dimensions, not unit scales. It does not convert cm to m, minutes to seconds, degrees Celsius to kelvin, or other scaled/offset units. Unknown symbols are rejected rather than guessed.

## Rules

- Addition and subtraction require equal dimensions.
- Multiplication adds dimension exponents; division subtracts them.
- A numeric constant exponent scales the base dimensions.
- A variable exponent is allowed only when both base and exponent are dimensionless.
- `sqrt` halves dimension exponents; `abs` preserves dimensions.
- `exp`, `log`, `sin`, and `cos` require dimensionless arguments. Radians are dimensionless in this checker.
- The output's declared unit must match the dimension derived from its expression.
- Explicit unit declarations are included in the source revision hash, so changing a declaration invalidates stale simulation requests.

## Example

```text
unit(I)=A；
unit(R)=ohm；
unit(U)=V；
unit(P)=W；
P=U*I；
U=I*R。
```

The dependency order is `U` then `P`. For I=2 and R=4, the numerical outputs are U=8 V and P=16 W.

The following must be rejected:

```text
unit(m)=kg；
unit(a)=m/s^2；
unit(F)=J；
F=m*a。
```

The expression has dimensions kg*m/s^2 (newtons), not joules.

## Trust and safety boundary

A `verified` result means only that all variables were explicitly annotated and the equation graph is dimensionally self-consistent under this limited SI symbol table. It does **not** establish that:
- the source text is true or correctly transcribed;
- the selected units are physically appropriate;
- the equation is physically valid, causally meaningful, or applicable in the current regime;
- numeric values have correct provenance or calibration;
- unit conversions, uncertainty propagation, or measurement tolerances are correct.

The unit declarations remain user-supplied assertions. The AI must not silently invent or overwrite them.

## Next V1.9 increments

1. **AI model proposal, not execution:** propose variable definitions, unit declarations, equation candidates, assumptions, and exact evidence spans. Keep each proposal separate from source evidence; require deterministic validation and explicit human confirmation.
2. **Causal state machine:** introduce explicit state variables, initial conditions, guarded transitions, invariants, and intervention semantics. Do not infer causation from correlation or from an algebraic dependency edge.
3. **3D experimental apparatus:** bind validated model variables to a small declarative set of visual components and transforms. Keep rendering separate from the solver; no model-supplied JavaScript, dynamic imports, or arbitrary code.
4. **Validation:** test dimensional counterexamples, invalid transitions, invariant violations, determinism, and bounded execution. Add real browser/WebGL evidence only after the actual browser environment is available.
